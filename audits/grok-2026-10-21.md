## Threat model

Enarratio protects a page from chart data becoming markup, and the gallery from being framed, scripted, or logged as reader traffic. Callers are site authors (server render), the page's own script (`enhance` and `update`), and anonymous browsers (the gallery). There is no account, no session, and no MCP server.

Entry points:

- Server functions in `enarratio`, `enarratio/plot`, `enarratio/science`, and `enarratio/lite`. Each returns an HTML string. Trust changes where caller strings enter attributes or text. `escapeHtml`, `element`, `text`, and `serialize` escape those strings. `children` passed to `element` and `el` is trusted markup.
- `href` on `barChart`. `safeHref` in `src/render/bar-model.ts` accepts relative and `http:` or `https:` links and throws otherwise. Lite bars call the same model.
- `stylesheet` and `defineTheme`. Names, fonts, and scheme selectors pass `assertCssText`. Colors are hex, or for per-series overrides `cssColor`.
- `enhance` and `update` in the browser. `update` parses with `DOMParser` and `sanitize` before `importNode`. Tooltips use `textContent`.
- Gallery Worker `worker/index.ts`: HTTP and the old hostname redirect, `POST /csp-report` goes to site-runtime's `receiveCspReport`, everything else is the assets binding. `wrangler.jsonc` holds no account id and no secret.
- CI: push and pull request run typecheck, lint, unit tests, build, size, pack, browser tests, worker size, and the AI-author check. Push to `main` also deploys the gallery and publishes a code map. A version bump on `main` tags and stages npm. A `v*` tag starts consumer bumps.

STRIDE, short: spoofing is a chart link whose host is hidden in userinfo (EN-3). Tampering is markup injection, which the escape path and the hostile suite cover, with two attribute gaps in `sanitize` (EN-4). Repudiation does not apply. Information disclosure is the repo settings (EN-1, EN-8) and CSP reports, which the pinned receiver logs without the query string. Denial of service is a huge chart, and the time axis throws past its bar cap. Elevation is a push to unprotected `main` running install and deploy with the tokens in EN-1.

## Findings

### EN-1 Major. Unprotected main, secret scanning off, and write-token workflows

Area: supply chain. Confidence: confirmed.

`main` has no branch protection (HTTP 404) and the ruleset list is empty. `security_and_analysis` reports dependabot security updates disabled, secret scanning disabled, push protection disabled, and the non-provider and validity checks disabled. A direct push to `main` is the gallery deploy, the code map, and, when `package.json` changes, the release tag.

`.github/workflows/code-map.yml` lines 27 to 32 grant `contents: write` and call devkit `27e0a1ca`. That workflow's map job (same sha, lines 99 to 126) checks out with `persist-credentials: false` and then runs `bash -c` for install, coverage, and mutation. The caller does not pass `install`, so the default is `npm ci`. Coverage is `npx vitest run --coverage...`. The mutation command is empty on a push and, on the Monday schedule and on `workflow_dispatch`, is the Stryker install and the chunk loop, also via `bash -c`. The publish step (lines 529 to 544) sets `GITHUB_TOKEN` from `github.token` and force-pushes the `code-map` branch. `persist-credentials: false` removes the git credential helper. It does not remove the token from the job.

`.github/workflows/gallery.yml` lines 21 to 23 put `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in the job environment, then run `npm ci` and `npm run deploy:gallery`. `.github/workflows/release.yml` lines 41 to 42 grant `contents: write` on `main` and tag whatever version `package.json` holds. `.github/workflows/bump-consumers.yml` lines 15 to 32 run on every `v*` tag, pass `RENOVATE_TRIGGER_TOKEN`, and set `dry_run` from an expression that is false on a tag push (EN-9). `.github/workflows/visual-snapshots.yml` has workflow-level `contents: write` and force-pushes an orphan branch. It is `workflow_dispatch` only.

Path: a person or a stolen write token pushes to `main`. The new commit's install scripts and the coverage command run in the code-map job, which holds a token that can push `code-map`. The gallery job's `npm ci` runs with the Cloudflare token in the environment. Nothing requires a review first, and a pushed secret is not blocked by push protection.

Smallest fix: protect `main` with a required pull request. Turn secret scanning and push protection on. Split the code-map work so `npm ci`, vitest, and Stryker run in a job with `contents: read`, and a later job that only publishes the two JSON files holds `contents: write`.

### EN-2 Minor. The live HTTP redirect is not the Worker's

Area: Cloudflare, live check. Confidence: confirmed for GET. A POST was not sent.

`worker/index.ts` lines 34 to 40 answer `http:` with 301 for GET and HEAD and 308 otherwise, `Cache-Control: no-store`, and the gallery security headers. Unit tests cover that. A GET of `http://enarratio.dustinedwards.info/` on 2026-10-21 returned 301 to the https URL with `Content-Type: text/html; charset=UTF-8` and without `Cache-Control`, CSP, or the rest of the set. A GET of `https://abscissa.dustinedwards.info/` returned 301 with `Cache-Control: no-store` and the full set, which matches `respond()`. The current host's plain HTTP redirect is produced in front of the Worker. The 308 that keeps a POST a POST does not run for that host.

Path: a client posts to `http://enarratio.dustinedwards.info/csp-report`. The edge 301 can turn that into a GET and drop the body before the Worker sees it. CSP reports from an https page use a relative `report-uri`, so they stay on https. The gap is any client that still uses the http URL.

Smallest fix: on the zone, let this hostname's http requests reach the Worker, and re-check that an http GET carries `no-store` and the security headers.

### EN-3 Minor. `https` links may hide another host in the userinfo

Area: security. Confidence: confirmed by running.

`safeHref` (`src/render/bar-model.ts` lines 213 to 220) strips characters at or below U+0020, rejects a leading `//` or backslash pair, and rejects any scheme other than `http` and `https`. It returns the original string. `safeLink` (`src/enhance/sanitize.ts` lines 42 to 46) uses the same scheme rule. Neither looks at the username or password.

A probe called `barChart` with `href` returning `https://dustinedwards.info@evil.example/login`. The call returned markup containing that URL. The same URL, passed through `sanitize` on a parsed figure, was kept as `href`. `javascript:`, ` java\tscript:`, `data:`, and protocol-relative forms throw, and those tests went red when the throw was removed.

Path: a site passes row data through `href`. A value whose userinfo looks like a trusted host and whose real host is someone else becomes a clickable bar. The visible label can be the series name, so the address is the part a reader does not see until they follow it.

Smallest fix: parse with `URL` when a scheme is present and throw when `username` or `password` is set. Apply the same rule in `safeLink`.

### EN-4 Minor. `sanitize` keeps attributes the server does not emit

Area: security. Confidence: confirmed by running.

`update` parses markup, calls `sanitize`, then `importNode` (`src/enhance/chart.ts` lines 505 to 527). `src/enhance/types.ts` lines 56 to 58 say only the elements and attributes Enarratio emits are kept. `sanitize` (`src/enhance/sanitize.ts` lines 49 to 69) removes elements outside the allowlist and strips `on*` attributes, `srcdoc`, `formaction`, a `style` that fails `SAFE_STYLE`, and an `href` or `xlink:href` that fails `safeLink`. Every other attribute stays.

A probe sanitized a figure that contained a `javascript:` link, an `https` link with `ping`, a `button` with `form="publish"` and `type="submit"`, and an SVG `set` whose `to` was `javascript:`. After `sanitize`: the `javascript:` href was gone, the `set` element was gone, the userinfo `href` and `ping="https://evil.example/p"` remained, and the button still had `form` and `type="submit"`. The browser test `F11` checks handlers, `img`, `script`, and a `javascript:` href. It does not check `ping` or `form`. That test lives in `test/browser/review.test.ts` and passed in CI on this SHA. The unit suite does not call `update`.

Path: a page calls `chart.update` with markup an attacker can influence. A `ping` attribute beacons on click. A `button type="submit" form="..."` submits a form already on the page. Script, `foreignObject`, `use`, `image`, and `set` do not survive.

Smallest fix: keep an attribute allowlist next to the element allowlist (the `data-enarratio-*` names, `aria-*`, href after `safeLink`, presentation attributes the SVG uses, `class`, `id`, `role`, and the custom-property `style`). Drop `ping`, `form`, and anything else absent from that list.

Smallest fix: bump the dev range that pulls `vite` past 8.3.2 when a fixed release exists, and add `npm audit --audit-level=high` to the CI job that already runs `npm ci`.

### EN-9 Minor. A hand-pushed tag bumps consumers before npm approval

Area: supply chain, release. Confidence: confirmed.

`docs/releasing.md` says a merge to `main` stages the package and that it stays hidden until a maintainer approves it with 2FA. ### 5. Correctness

The time-axis bar path throws when the span would need more bars than its cap. `validateFigure` requires a non-empty `alt` and a positive finite size.
